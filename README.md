# ER — Error Radar

**주소만 넣으면 화면을 돌면서 "눌러도 아무 일도 안 일어나는 버튼"까지 찾아내는 자동 스모크 테스트 도구**

</div>

---

## 왜 만들었나

개발팀이 기본 확인 없이 QA로 넘기면, *"이거 한 번이라도 눌러보셨어요?"* 소리가 나오는 결함을
QA가 손으로 걸러내는 데 시간이 갑니다. 그 수준은 자동으로 거를 수 있습니다.

일반적인 모니터링 도구는 **에러**는 잡지만 **"클릭해도 아무 일도 안 일어나는" 상태**는 놓칩니다.
에러가 나지 않기 때문입니다. ER은 클릭 전후의 변화를 관찰해 이 **무감(NO-RESPONSE)** 결함까지 판정합니다.

---

## 무엇을 판정하나

화면에서 `button`, `a`, `[role=button]`, `[onclick]` 요소를 모두 수집해 하나씩 클릭하고,
다섯 가지 신호(화면 구조 · 서버 요청 · 주소 이동 · 화면 표시 · JS 예외)의 변화를 관찰합니다.

| 판정 | 기준 |
|:---|:---|
| **정상** | 변화 신호가 하나 이상 관찰됨 |
| **에러** | JS 예외 발생 또는 서버가 4xx·5xx 응답 |
| **무감** | 클릭은 됐으나 모든 신호가 무변화 |
| **검사 제외** | 비활성 요소, 외부 링크, 삭제·결제 등 눌리면 곤란한 버튼 |

**요소를 보고 판정합니다. 버튼 이름이나 기획 의도는 보지 않습니다.**
이름을 보는 곳은 제외 규칙 한 군데뿐이며, 이는 판정이 아니라 안전장치입니다.

---

## 무감 판정을 어떻게 신뢰할 수 있나

무감 판정의 어려움은 **페이지가 스스로 만들어내는 변화**에 있습니다.
시계·배너·캐러셀이 하나만 돌아가도 화면은 계속 바뀌므로, 단순히 "화면이 바뀌었나"로 판정하면
모든 버튼이 정상으로 나옵니다.

ER은 변화의 **횟수**가 아니라 변화가 일어난 **위치**로 구분합니다.
페이지에 들어가면 먼저 클릭 없이 한 번 관찰해 저절로 바뀌는 지점들을 기록해두고,
그 목록에 없는 위치에서 일어난 변화만 신호로 인정합니다.

`test-target.html` 은 1초마다 갱신되는 시계를 일부러 넣은 검증용 페이지입니다.
`npm test` 로 13개 요소의 기대 판정과 실제 판정을 대조합니다.

```
판정 정확도   통과 13/13 — 오탐 0건
로그인 자동화 통과 5/5
```

같은 페이지에서 위치 기반 판별을 적용하기 전의 엔진은 무감 2건을 모두 정상으로 놓쳤습니다.

## 빠른 시작

Node.js 20 이상이 필요합니다.

```bash
npm install          # 검사용 브라우저(Chromium)까지 함께 설치됩니다
npm test             # 판정이 정확한지 검증 (13/13 통과해야 정상)
npm start            # 웹 화면 → http://localhost:3000
```

명령줄로도 쓸 수 있습니다. 결함이 있으면 종료 코드 1로 끝나므로 배포 파이프라인의 게이트로 쓸 수 있습니다.

```bash
node scan.js https://example.com --scope path --observe 2000
```

자세한 사용법은 **[사용 설명서](MANUAL.md)** 를 보세요.

## 어디서 실행해야 하나

검사 엔진은 **실행되는 PC의 네트워크로** 대상에 접속합니다. 그래서 실행 위치가 곧 검사 가능 범위입니다.

| 실행 위치 | 사내·개발 주소 검사 |
|---|:---:|
| 사내 서버 | 가능 — 팀 전체가 함께 쓰는 최종 형태 |
| 검사자 PC | 가능 — 그 PC의 네트워크·VPN을 그대로 사용 |
| 외부 클라우드 | **불가** — 사내망 밖이라 주소에 닿지 못함 |

사내 주소가 주 대상이라면 **사내망 안에서 실행해야 합니다.**
`Dockerfile` 이 포함돼 있어 사내 서버에 그대로 올릴 수 있고, 올린 뒤에는 팀원이
`http://서버주소:3000` 으로 접속해 씁니다. 프로젝트·검사 기록·저장된 로그인은 서버에 남아
접속한 모든 사람이 공유합니다.

화면이 없는 서버에서는 "직접 로그인"(브라우저 창을 띄워 사람이 로그인하는 방식)을 쓸 수 없으며,
ER 이 이를 감지해 안내합니다.

외부 클라우드 배포는 공개 URL 검사와 데모 용도로만 의미가 있습니다.
`Dockerfile` 이 포함돼 있으며, Playwright 공식 이미지를 사용해 브라우저 설치 문제를 피합니다.

## 구조

| 파일 | 역할 |
|---|---|
| `src/engine.js` | 판정 엔진 — 클릭, 변화 관찰, 노이즈 판별, 4단계 분류 |
| `src/crawler.js` | 페이지 순회 — URL 정규화, 범위 제한, 방문 관리 |
| `src/login.js` | 로그인 — 자동 입력, OTP, 직접 로그인 창 |
| `src/projects.js` | 프로젝트 — 주소·로그인·규칙을 대상별로 저장 (`data/`, git 제외) |
| `src/totp.js` | 인증 앱 OTP 코드 생성 (RFC 6238) |
| `src/reporter.js` | HTML·엑셀 리포트 생성 |
| `server.js` | 웹 서버 (Express + Socket.IO) |
| `scan.js` | 명령줄 실행 (`--project` 로 프로젝트 지정) |
| `test/verify.js` | 판정 정확도 회귀 테스트 |
| `test/verify-login.js` | 로그인 자동화 회귀 테스트 |
| `test-target.html` | 판정 검증용 대상 페이지 (기대 판정이 정해져 있음) |
| `test-login.html` | 로그인 검증용 화면 (이름 없는 입력칸·form 없음·OTP) |
| `config.json` | 새 프로젝트의 처음 규칙 |

기획 배경과 기능 명세는 [기획안](기획안_자동스모크테스트.md) · [기능정의서](기능정의서_자동스모크테스트.md) 에 있습니다.
